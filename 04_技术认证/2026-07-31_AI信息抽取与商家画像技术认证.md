# AI 信息抽取与商家画像技术认证

## 1. 技术目标

验证 AI 是否能稳定完成以下任务：

- 从聊天内容中提取商家需求
- 区分商家明确表达和系统推测
- 生成可执行的作画任务书
- 将本次需求沉淀为商家长期画像
- 在老客户再次下单时复用历史画像

## 2. 推荐技术架构

### MVP 架构

```text
前端页面
  -> 输入聊天文本或截图
  -> 后端接口
  -> OCR 服务
  -> AI 需求抽取
  -> 结构化结果
  -> 数据库存储
  -> 商家画像更新
```

### 数据库建议

MVP 可以使用：

- SQLite：适合本地工具或早期验证。
- PostgreSQL：适合后续 Web 产品和多人使用。

### AI 调用建议

AI 输出必须结构化，建议让模型输出 JSON，再渲染成任务书。

不要只保存自然语言总结，否则后续难以检索、合并和分析。

## 3. 需要验证的关键问题

### 3.1 聊天内容是否能稳定提取需求

测试方法：

- 准备 20 组真实或模拟商家聊天。
- 人工标注商家需求。
- 对比 AI 提取结果是否遗漏关键信息。

通过标准：

- 关键需求召回率达到 80% 以上。
- 待确认问题能指出主要模糊点。

### 3.2 AI 是否能区分事实和推测

系统输出需要分层：

- 商家明确说过
- 根据上下文推测
- 需要进一步确认

通过标准：

- AI 不把推测内容写成确定需求。
- 冲突信息能进入待确认问题。

### 3.3 商家画像是否能长期累积

画像更新不能简单覆盖旧内容。

推荐策略：

- 新增偏好：直接追加。
- 重复偏好：提高权重。
- 冲突偏好：标记为可能变化。
- 单次异常：只记录到本次项目，不直接更新长期画像。

通过标准：

- 老客户 3 次项目后，画像能体现稳定偏好。
- 单次特殊项目不会污染长期偏好。

## 4. OCR 技术认证

MVP 的截图 OCR 需要重点验证：

- 微信聊天截图识别准确率
- 多张截图顺序处理
- 商家和画师发言区分
- 表情、图片、语音占位的处理方式

建议先做半自动：

1. OCR 提取文字。
2. 画师手动检查。
3. 确认后再交给 AI 分析。

这样可以降低早期风险。

## 5. Prompt 输出结构建议

AI 分析时需要固定输出：

```json
{
  "summary": "",
  "merchant_keywords": [],
  "explicit_requirements": [],
  "inferred_requirements": [],
  "style_direction": {
    "art_style": "",
    "color": "",
    "mood": "",
    "references": []
  },
  "drawing_goal": "",
  "main_subject": "",
  "must_have": [],
  "avoid": [],
  "questions_to_confirm": [],
  "artist_brief": "",
  "profile_update_suggestions": {
    "new_preferences": [],
    "reinforced_preferences": [],
    "possible_changes": [],
    "communication_notes": []
  }
}
```

## 6. 隐私和安全

聊天截图可能包含：

- 微信昵称
- 手机号
- 地址
- 价格
- 商业方案
- 未公开品牌物料

需要设计：

- 删除原始素材
- 脱敏展示
- 本地存储或加密存储
- 导出前提醒
- 商家档案删除

## 7. 技术结论

建议先做“文本输入 + 结构化 AI 输出 + 商家画像保存”的 MVP。

截图 OCR 和参考图理解可以作为第二阶段能力，不要放在第一版阻塞核心验证。
