# 聊天需求提取与商家画像 SPEC

## 1. 功能目标

让画师把商家聊天内容或截图交给系统后，系统自动整理出本次作画需求，并将商家的长期偏好沉淀到独立画像中。

## 2. 用户流程

### 2.1 新客户首次下单

1. 画师创建商家档案。
2. 输入商家名称、行业、联系方式备注等基础信息。
3. 上传聊天截图或粘贴聊天文本。
4. 系统提取本次需求。
5. 系统生成作画任务书。
6. 画师检查、编辑、确认。
7. 系统把确认后的需求写入商家历史记录。
8. 系统更新商家画像。

### 2.2 老客户再次下单

1. 画师打开已有商家档案。
2. 新建一次需求分析。
3. 上传本次聊天内容。
4. 系统同时参考历史画像和本次聊天。
5. 系统生成本次作画任务书。
6. 系统提示本次需求与历史偏好的相同点和不同点。
7. 画师确认后保存到历史记录。

## 3. 输入内容

### 3.1 聊天文本

支持直接粘贴：

- 微信聊天文字
- 商家需求说明
- 修改意见
- 画师自己的备注

### 3.2 聊天截图

MVP 可先支持图片上传，由 OCR 提取文字。

截图内容包括：

- 商家发言
- 画师回复
- 图片描述
- 修改意见

注意：系统需要区分“商家说的话”和“画师说的话”。

### 3.3 参考图

MVP 可先允许上传参考图并填写人工备注。

后续版本再增强图片理解能力。

## 4. 输出一：本次需求分析

系统应输出以下字段：

### 4.1 商家原始诉求摘要

用简短文字说明商家这次想做什么。

### 4.2 关键词

提取商家反复出现或影响创作方向的词。

示例：

- 可爱
- 国潮
- 高级感
- 节日氛围
- 亲子
- IP 形象
- 招财
- 年轻化

### 4.3 作画目的

说明画面最终要服务什么商业目的。

可能包括：

- 品牌宣传
- 商品包装
- 活动海报
- 节日营销
- 门店物料
- 社交媒体传播
- 客户头像或 IP 形象

### 4.4 画面主体

说明画面里主要要画什么。

字段包括：

- 主体类型
- 角色数量
- 角色身份
- 角色动作
- 角色表情
- 服饰道具
- 背景元素

### 4.5 风格方向

整理商家表达出的风格倾向。

字段包括：

- 美术风格
- 线条感觉
- 色彩倾向
- 氛围关键词
- 参考风格
- 不喜欢的风格

### 4.6 必须满足项

商家明确说过必须要有的内容。

### 4.7 可发挥项

商家没有明确限制，画师可以创作发挥的内容。

### 4.8 待确认问题

系统需要把模糊、有冲突、缺失的信息列出来，方便画师回问商家。

示例：

- 商家提到“高级一点”，但没有说明更偏商务高级还是可爱精致。
- 商家说要“突出产品”，但未提供产品主视觉。
- 商家既要“简洁”又要“元素丰富”，需要确认优先级。

## 5. 输出二：作画任务书

作画任务书是给画师看的最终执行文档。

建议结构：

```text
项目名称：
商家名称：
本次作画目的：
使用场景：

画面主题：
画面主体：
角色/形象设定：
风格方向：
色彩氛围：
构图建议：
必须包含：
避免出现：
参考信息：

待确认问题：
画师备注：
```

## 6. 输出三：商家画像

商家画像是长期保留的信息。

### 6.1 基础信息

- 商家名称
- 行业
- 联系人备注
- 品牌关键词
- 常见使用场景

### 6.2 偏好信息

- 偏好的画风
- 偏好的色彩
- 偏好的角色气质
- 偏好的构图方式
- 常用参考类型
- 经常强调的点

### 6.3 沟通风格

- 表达是否具体
- 是否经常临时改需求
- 喜欢用哪些词描述画面
- 是否需要画师主动给方案
- 对价格、周期、细节的敏感程度

### 6.4 历史项目

每次项目记录：

- 项目名称
- 日期
- 原始聊天内容摘要
- 最终任务书
- 最终交付风格
- 修改记录
- 复盘结论

### 6.5 后续接单建议

系统根据历史总结：

- 开始沟通时应优先确认什么
- 推荐使用什么风格
- 哪些表达要追问
- 哪些内容不能踩雷

## 8. 重要产品原则

- AI 生成的内容必须可编辑。
- 原始聊天记录必须可追溯。
- 商家画像不能被一次聊天轻易覆盖，应追加和合并。
- 必须区分“明确需求”和“系统推测”。
- 对隐私内容要有保护意识，截图和聊天内容需要可删除。
